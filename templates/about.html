How I work

Three habits worth stating

Write the doc before the code

DeepCS had a locked design document with nine ADRs before the first service existed. Not because documentation is virtuous, but because it's the cheapest place to find out that an idea doesn't work. The doc is also where rejected options get recorded, and an ADR only earns its place when the option that lost was genuinely defensible.

Name the tradeoff you're accepting

Six deployables means a cold match request can chain cold starts. One Postgres instance means a shared failure domain. Buying auth means a revoked token stays valid for up to an hour. Those are written down as accepted costs, with the condition that would change the decision. They are not left out because they're inconvenient.

Report p95, never the average

If 95 requests take 10 ms and 5 take 2 s, the average is 110 ms and not one request was anywhere near it. The tail is what a user feels, and it's where queueing, contention and cold starts show up first. The same instinct is why this site marks what's designed versus what's running.
