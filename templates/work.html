[why v1 existed]

I wanted to learn distributed systems by running into their problems rather than reading about them, so I built six services on purpose: atomic claims, cross-instance pub/sub, an at-least-once event log, a rate limiter that had to be a Lua script. That was a good reason to build it. It was not a good reason to keep it.

[why v2 replaced it]

User feedback showed no demand for the collaborative half, which was the part I was proudest of. Six services became four handlers in one Worker, two managed databases became one SQLite file at the edge, and idle cost went to zero.

[what survived]

Every enforcement property. One place decides who you are, the user id comes from the verified token and never from the request, the paywall is server-side, and every write a webhook makes is idempotent. Deleting code is only safe if you know which parts were load-bearing.

Cutting it was the right call and it was not a comfortable one. Being able to build a thing is a separate question from whether it should exist, and I would rather learn that on my own product than on someone else's.

Underneath sits a test suite of unit, integration and end-to-end tests, running in CI on every push, because a solo project has no second pair of eyes on a pull request. There is more in the repo than fits here, including the atomic rate limiter, the replayable event log, and the reasoning behind every service boundary I drew and later erased. Nine architecture decision records live in DESIGN.md, including why I built the gateway instead of using Kong, and why auth is the one thing I paid for.

01

Where I drew the build-buy line

one founder, finite hours

A solo founder's real constraint is attention, not skill. Every hour spent rebuilding something boring is an hour not spent on the thing customers actually see. This is where I put the line, and why.

[built]

The storefront. React and TypeScript, reusable components and one central place for state rather than a prop threaded through six levels. This is what a customer forms an opinion from in about four seconds, so it was worth writing myself rather than fighting a theme.

[bought]

Checkout. Shopify takes the card, the tax, the fraud rules and the PCI scope. There is no version of me building that better in a fortnight, and payments is the one area where a subtle mistake is somebody else's money rather than my time. Payments and compliance stayed off my plate on purpose.

[built]

Everything that is not code. The brand, the bottles, the photography, the copy, the pricing and the fulfilment. Engineers who have only ever received requirements do not find out what it costs to decide them. I decided all of them, and shipped anyway.

[what it taught me]

The same instinct runs through DeepCS: build the part that is yours, buy the part that is solved, and be honest about which is which. Buying auth and payments there was the same decision as buying checkout here, made with more evidence.

It ran from December 2025 to March 2026, from an empty repo to a live storefront with people using it. Following a product all the way through to real users is a different job from finishing a feature, and it is the part I would not have learned any other way.
